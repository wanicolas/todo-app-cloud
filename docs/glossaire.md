# Glossaire Technique

Ce glossaire répertorie et définit les principaux termes techniques utilisés dans le cadre de ce projet.

| Terme                                   | Définition                                                                                                                                                                                                                                                         |
| :-------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **12-Factor App**                       | Une méthodologie de conception d'applications logicielles SaaS modernes cloud-natives, articulée autour de 12 grands principes (base de code unique, dépendances explicites, configuration par variables d'environnement, parité dev/prod, etc.).                  |
| **AKS (Azure Kubernetes Service)**      | Le service Kubernetes managé par Microsoft Azure, permettant de déployer, gérer et mettre à l'échelle des conteneurs dans le cloud.                                                                                                                                |
| **ACR (Azure Container Registry)**      | Le registre d'images Docker privé managé par Azure, servant à stocker de manière sécurisée les images de nos microservices.                                                                                                                                        |
| **Azure Key Vault**                     | Un service cloud sécurisé proposé par Azure servant à stocker, chiffrer et contrôler l'accès aux secrets, mots de passe et certificats TLS/SSL.                                                                                                                    |
| **Bounded Context (Contexte Délimité)** | Concept issu du Domain-Driven Design (DDD) définissant une frontière explicite à l'intérieur de laquelle un modèle de domaine (code, données, termes) est applicable de manière uniforme (ex. Contexte d'authentification vs Contexte de tâches).                  |
| **Chart Helm**                          | Un paquet Helm contenant des modèles de manifestes Kubernetes (templates) combinés à des fichiers de configuration (`values.yaml`) permettant de déployer une application complexe de manière reproductible.                                                       |
| **Graceful Shutdown (Arrêt Gracieux)**  | Le processus consistant à arrêter proprement une application (par exemple, un serveur web Express) en arrêtant d'accepter de nouvelles connexions, en terminant les requêtes en cours, puis en fermant les connexions réseau et BDD avant d'éteindre le processus. |
| **Helm**                                | Le gestionnaire de paquets de référence pour Kubernetes, facilitant le déploiement, la mise à jour et la gestion du cycle de vie des applications conteneurisées.                                                                                                  |
| **JWT (JSON Web Token)**                | Un standard ouvert (RFC 7519) définissant un moyen compact et sécurisé de transmettre des informations entre les parties sous forme d'objet JSON signé de manière cryptographique (ici, en HS256).                                                                 |
| **Knex.js**                             | Un constructeur de requêtes SQL (Query Builder) pour Node.js prenant en charge plusieurs dialectes (MySQL, SQLite3) et permettant le versioning de la base de données via des migrations.                                                                          |
| **Monorepo**                            | Une stratégie de développement logiciel où le code de plusieurs projets ou microservices est stocké dans un seul et unique dépôt Git (ici : backend, client, auth, infra).                                                                                         |
| **Non-Root Container**                  | Pratique de sécurité consistant à configurer les conteneurs Docker pour s'exécuter sous un utilisateur non-privilégié (ex. l'utilisateur `node` ou `nginx` sur port unprivilégié) plutôt que `root`, réduisant la portée d'une éventuelle faille.                  |
| **Reverse Proxy (Nginx)**               | Un serveur intermédiaire chargé de recevoir les requêtes des clients, de gérer le chiffrement TLS/HTTPS, puis de les acheminer vers le microservice approprié dans le cluster.                                                                                     |
| **Secrets Store CSI Driver**            | Un pilote d'interface de stockage Kubernetes (CSI) permettant de monter des secrets stockés dans des coffres-forts externes (comme Azure Key Vault) directement sous forme de volumes de fichiers à l'intérieur des conteneurs.                                    |
| **TLS/SSL**                             | Protocoles de sécurisation des échanges sur internet assurant la confidentialité (chiffrement) et l'intégrité des flux de données en transit.                                                                                                                      |
| **Trivy**                               | Un scanner de sécurité open source utilisé pour détecter les vulnérabilités (CVE) dans les packages système et les dépendances au sein des images de conteneurs.                                                                                                   |
